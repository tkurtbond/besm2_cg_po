In `~/current/RPG/Tools/BESM/` there are four versions of a program that takes characters for the Big Eyes Small Mouth 2nd Edition Revised (BESM2ER) RPG expressed as YAML files and totals up their costs and formats them in various ways for printing or for use in other documents. The original program is besm2-rst.scm, besm2-rst-f.scm uses the slibfyaml binding (from `~/Repos/Scheme/Chicken/5/slibfyaml/` ) to libfyaml.  besm2-rst-e.scm separates out the entity handling code and stores the entities in structures, rather than constantly reparsing the information out of raw alists.  besm2-rst-f-e.scm is the combination of besm2-rst-f.scm and besm2-rst-e.scm.

There is an equivalent Ada program in `~/Repos/RPG/Tools/besm2_fmt/` (which uses the alibfyaml binding to libfyaml in `~/Repos/Ada/alibfyaml`) and two versions in Oberon-2 using the Vishap Oberon compiler (voc) in `~/Repos/RPG/Tools/obesm2_fmt` (which uses normal Oberon-2 text procedures) and `~/Repos/RPG/Tools/obesm2_fmt2/` (which used a Ropes library from `~/Repos/Oberon/Ropes/` , both of which use the olibfyaml binding to libfyaml in `~/Repos/Oberon/olibfyaml/` .  Finally, there is another Oberon-2 version in `~/Repos/RPG/Tools/pobesm2_fmt2/` which uses the Peaseblossom Oberon Compiler (poc) in `~/Repos/Oberon/Peaseblossom/` and the polibfyaml binding to libfyaml for Peaseblossom Oberon in `~/Repos/Oberon/polibfyaml/` along with the Ropes library mentioned above.

All of these programs should produce the same output, given the same input.

A bookmarked copy of the BESM2ER rulebook is in `~/Reference/RPG/Dyskami/BESM/2E/BESM2ER_bookmarked.pdf`, and a text version created by pdftext is in `~/Reference/RPG/Dyskami/BESM/2E/BESM2ER-nolayout.text` and a text version created by "pdftext -layout" is in `~/Reference/RPG/Dyskami/BESM/2E/BESM2ER-layout.text`.

There is also the BESM Retro 2nd Edition (BESMR2E), which was a republication of BESM2ER with some updates.  The pdf is in `~/Reference/RPG/Dyskami/BESM/2E/dys_besm_retro_second_edition_v1_0_3.pdf`, with text versions in `~/Reference/RPG/Dyskami/BESM/2E/dys_besm_retro_second_edition_v1_0_3-layout.text` and `~/Reference/RPG/Dyskami/BESM/2E/dys_besm_retro_second_edition_v1_0_3-nolayout.text`.  Perhaps this can be used to resolve some of the open questions resulting from BESM2ER's text.

### BESM 1st Edition (BESM1E)

The BESM 1st Edition PDFs are in `~/Reference/RPG/Dyskami/BESM/1E/`, each with `-layout.text` and `-nolayout.text` versions made by `pdftotext` (one form feed per PDF page):

- `Big_Eyes_Small_Mouth_First_Edition.pdf` (87 pages): the 1st Edition rulebook.
- `GdOr-BESM_FirstEdition.pdf` (87 pages): another copy of it.  Its pages carry the purchaser line, like BESM2ER.pdf's, so filter out `order #` whenever you read it.
- `Big_Robots_Cool_Starships.pdf` (111 pages): BRCS, the 1st Edition mecha book.  Some fixture characters (the FV2021 Coleopteran) were converted from it to BESM2ER, so it explains names like Armour, Partial Armour and Super-Strength in those files.
- `Hot_Rods_and_Gun_Bunnies.pdf` (123 pages): the 1st Edition vehicles and weapons book.

Use these only to explain names and numbers in existing files; the rules the programs compute are BESM2ER's.


Finally, there is a Peaseblossom Oberon Oberon-2 program ova_cg_po (in `~/Repos/RPG/Tools/ova_cg_po/`) using polibfyaml and pofltk (`~/Repos/Oberon/pofltk/`) that is a character generator for the OVA RPG.

The goal of this project is to analyze the BESM2ER rules and see if the YAML representation of BESM2ER characters needs to be extended in any way, and then create a character generator called `besm2_cg_po` for BESM2ER using polibfyaml and pofltk, which does all the calculations necessary for derived character values and keep track of character points, bonus points, and skill points.  It is ok to list character stats, abilities, defects, skills, weapon attack abilities, and weapon attack disabilities by name, so that the user of the character generation program can pick them to create the character, but none of the description of those items should be included in the character generator for copyright reasons. Instead, any presentation of the names of those items should include the page number in the rulebook they are on, and the program should be able to open that page in a PDF viewer so the user can reference the description easily.  (The ova_cg_po program does this for OVA's Abilities, Weaknesses, Perks, and Flaws.)

The plan for the analysis of the existing variants of the besm2-rst and besm2_fmt programs and for the creation of besm2_cg_po is in PLAN.md.  Record findings and decisions there, with their dates and rulebook pages, as the work goes.

## Decisions and observations

- **Pages.** The rulebook PDF has no page labels, and its page is the printed page + 2.  Whenever a program shows an item's page it must show both the printed page and the PDF page, e.g. `Highly Skilled (p. 42, PDF 44)`, so the user can use a paper copy, the book's own index, or the viewer's page box.  A PDF viewer is always sent the PDF page.  All pages come from one procedure (`Besm2Rules.Label`), so the format is the same everywhere.
- **The PDFs.** `~/Reference/RPG/Dyskami/BESM/2E/BESM2ER.pdf` is the original, and the `.text` files were made from it (one form feed per PDF page).  `BESM2ER_bookmarked.pdf` was made from it by combining it with a hand-typed list of bookmarks, and has no usable text layer (`pdftotext` gives dingbats).  Do text or font checks on `BESM2ER.pdf` or the `.text` files; open `BESM2ER_bookmarked.pdf` in the viewer.  The bookmarks (`mutool show BESM2ER_bookmarked.pdf outline`) were typed by hand, so use them as a second check on page numbers, not as the authority, and report any that disagree.
- **The existing formatters stay formatters.**  besm2-rst*.scm, besm2_fmt, obesm2_fmt, obesm2_fmt2 and pobesm2_fmt2 print what the YAML says and compute nothing; they only learn to print the new YAML keys.  All calculation lives once, in Oberon-2 modules with no window, shared by `besm2_cg_po` (the window) and `besm2_calc_po` (a command-line program in this repository that checks, fills in, upgrades and formats files).  The generator writes every number into the files it saves, so the formatters print them correctly.
- **YAML extensions** (PLAN.md, A4), all optional, so existing files load and print unchanged: `subject` on an attribute or defect (what used to follow `:` in the name; printed as `name: subject`); `level` on a defect; `damage`, `abilities`, `disabilities` (a name, or `{name, counts-as, detail}`), `primary` and `different-gunner` on a Weapon Attack; the mecha linked by Own a Big Mecha's `subject` being the mecha entity's `name`; `creation` on a character (`character-points`, `background-points`, `genre`, `skill-points`, `options`); `notes` on an entity (a list of short lines, never priced, printed after Skills); and `overrides`, the keys whose numbers the user typed.  Features or Accessories (p. 32) shows as "Accessories" on a mecha and "Features" otherwise.  `enhancements` and `limiters` stay as they are.
- **Order of changes to the YAML format:** the Ada besm2_fmt first, then the Oberon-2 ports (byte-for-byte with the Ada), then the Scheme programs.  Commit each repository on its own, only with the user's go-ahead.
- **Copyright.** Only names, costs, levels, limits and page numbers of rules items go in the code, tests or documents; never their descriptions.  Tests that need the rulebook's text read it from the PDF at test time.
- **pofltk 0.2.0** (`Fl.PofltkApiVersion` 200) is needed, since 2026-11-14, and 0.3.0 (300) by the tests, which drive the window with its `FlTest`.  Fill a Choice with `AddText`, which takes a label as it is; `Add` reads `/` as a submenu and `&` as a shortcut (PLAN.md, step 13).  Take text as an `Fl.String`, with no buffer to cut it short.  0.4.0 (400) is needed since 2026-11-14: a Choice is filled with `AppendText` (`AddText` with no shortcut or flags) and read back in tests with `ItemText`, a spinner's whole number is `IntValue`, a file chooser's answer is `Choose` (NIL if none), and `RequireDisplay` refuses a `DISPLAY` or `WAYLAND_DISPLAY` that names a display gone, by `Fl.CanOpenDisplay`.
- **Window tests** run on Xvfb or a headless sway, never on the user's desktop, as in ova_cg_po.
- Follow ova_cg_po's design, build and test setup, and copy pobesm2_fmt2's loader and formatter modules rather than rewriting them, renaming any that clash (`Besm2Cli`, `Besm2Fmt`).
